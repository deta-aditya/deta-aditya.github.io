# Deta Aditya personal website

Static portfolio for recruiters and hiring managers. Hosted on GitHub Pages at https://deta-aditya.github.io. Owner: Deta Aditya, senior fullstack engineer (TypeScript, React, FP, Clean Architecture).

## Your task
Turn the two working prototypes in `prototypes/` into a real Vite + React + TypeScript project, deployed to GitHub Pages with a GitHub Actions workflow. Keep the look and behaviour identical. Do not redesign.

## Owner preferences
- Explain the concept before implementation details. Friendly but professional. No flowery language.
- Never write em dashes in any public-facing text (site copy, README, docs).
- FP and immutable style: pure functions, readonly types, discriminated unions, no classes unless immutable. Functional Core, Imperative Shell.
- Reply in English.

## Site structure
Separate pages, not one long scroll. Shared navbar: Home, Experience, Projects, Writing, plus a "Hire me" button that opens a contact popover (email with copy button, LinkedIn, GitHub, Download CV).
- Use hash routes (`#/`, `#/experience`, `#/projects`, `#/writing`) so GitHub Pages needs no server rewrite. Experience deep link: `#/experience/<n>`.
- Desktop (min-width 900px and min-height 540px): every page fits one screen, NO vertical page scroll. Inner scroll is allowed only as a last resort in very short windows.
- Phones and short windows: pages may scroll normally.
- Navbar geometry must be identical on every page (same height, name, nav and button positions, same side padding `clamp(1rem, 4vw, 3.5rem)`). Verified at 390px and 1440px.
- Projects and Writing are not built yet (nav shows them disabled, "Coming soon").

## Prototypes (single-file HTML, generated)
- `prototypes/hero-b.html`: Home. Museum-encyclopedia style hero with six stages (Frontend, Backend, AI, Functional, Architecture, Fullstack) and 67 photorealistic cut-out specimens that move between stages. JS only sets `data-stage` on the hero; CSS owns all visuals and timing. Handoff `--out: 350ms`, `--gate: 500ms`, entrance delay `calc(var(--gate) + var(--k) * 12ms)`. Items carry per-stage positions as CSS custom properties. Mobile uses a separate layout (container query units). Items placed only on mobile have class `p-only`; items with no mobile fullstack spot need the pinned geometry rule `.s.fs.nfs-p`.
- `prototypes/experience.html`: Experience. Left role selector (company, years, mini timeline bar), right detail (kind, title, org, dates, bullets, tools, key figures). A `fit()` function adds `compact` or `tight` classes so desktop never scrolls. Role data lives in the `DATA` array.
Both are generated by Python from `tools/prototype-build/`. Treat the generated HTML as the visual spec and the Python as the source of the data: port `ITEMS` (in `build.py`) and `ROLES` (in `experience.py`) into typed TypeScript data modules, and port the CSS into CSS modules or one stylesheet per page. You do not need to keep the Python after the port.
